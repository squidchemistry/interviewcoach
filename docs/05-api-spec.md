# 05 · API Specification (v1)

- Base URL: `/api/v1`. JSON in and out (`application/json; charset=utf-8`) except uploads, SSE and webhooks.
- Type notation below is TypeScript-like shorthand for readability. The real contracts are Java `record` DTOs with
  Bean Validation, and the generated OpenAPI is authoritative.
- The machine-readable OpenAPI 3.1 document is **generated by springdoc** from the controllers and DTO records and
  served at `GET /v3/api-docs`, with Swagger UI at `/swagger-ui.html`. The frontend generates TS types from it. This file is the human-readable contract.
- **Auth column**: `—` public · `U` access token (any role) · `A` ADMIN · `C` refresh cookie · `S` webhook signature.
  The access token is sent as `Authorization: Bearer <jwt>`.
- **Pagination**: `?page=1&pageSize=20` (max 100) → `{ items, page, pageSize, total }`.
- **Idempotency**: commands that create turns accept `clientMessageId` (uuid). A replay returns the original result.
- Every response carries `X-Request-Id`. Rate-limited routes also return `RateLimit-Limit`, `RateLimit-Remaining`
  and `RateLimit-Reset`.

## 0. Error format (RFC 7807)

```json
{
  "type": "https://aicoach.dev/errors/invalid-transition",
  "title": "Invalid state transition",
  "status": 409,
  "code": "INVALID_TRANSITION",
  "detail": "Cannot SUBMIT_ANSWER while session is IN_PROGRESS/QUESTION",
  "requestId": "01JC3Z6V4W8Q2N7Y5K1H3T9F0M",
  "errors": [{ "path": "body.content", "message": "String must contain at most 8000 character(s)" }]
}
```

| HTTP | `code` | Meaning |
|---|---|---|
| 400 | `VALIDATION_ERROR` | Bean Validation failed (`errors[]` has field paths) |
| 401 | `UNAUTHENTICATED`, `TOKEN_EXPIRED`, `INVALID_CREDENTIALS` | |
| 402 | `QUOTA_EXCEEDED`, `PRO_REQUIRED` | free-tier limit / Pro-only feature |
| 403 | `FORBIDDEN` | role or ownership |
| 404 | `NOT_FOUND` | also used for resources owned by another user (no existence leak) |
| 409 | `EMAIL_TAKEN`, `INVALID_TRANSITION`, `STATE_CONFLICT`, `HINT_ORDER` | |
| 413 | `PAYLOAD_TOO_LARGE` | |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | |
| 422 | `RESUME_REQUIRED`, `RESUME_NOT_PARSED`, `NO_QUESTIONS_AVAILABLE`, `UNSUPPORTED_FOR_MODE` | semantically invalid |
| 429 | `RATE_LIMITED`, `TOKEN_BUDGET_EXCEEDED` | `Retry-After` set |
| 502 | `AI_INVALID_OUTPUT` | LLM output failed schema after retries |
| 503 | `AI_UNAVAILABLE`, `CODE_EXECUTOR_UNAVAILABLE`, `FEATURE_DISABLED` | upstream/circuit open |
| 500 | `INTERNAL` | generic, no internals leaked |

### 5.1 SSE stream contract — `GET /sessions/:id/stream`

- The client uses `fetch` streaming (`@microsoft/fetch-event-source`) so the `Authorization` header can be sent.
  It reconnects with `Last-Event-ID` and backoff from 1 s up to a 30 s cap.
- The event `id` is the Redis Stream entry id (e.g. `1730960000000-3`). On connect the server replays entries
  after `Last-Event-ID`, then blocks on `XREAD`. If the id is older than the retained window (MAXLEN ~2000 or
  24 h), the server sends `resync` and the client refetches `GET /sessions/:id`.
- A heartbeat comment line (`: ping`) is sent every 15 s. The server closes the stream on COMPLETED/ABANDONED
  after a final `state.changed`.

| `event:` | `data` (JSON) |
|---|---|
| `turn.started` | `{ turnId, kind: 'QUESTION'\|'FOLLOW_UP'\|'HINT', sessionQuestionId }` |
| `token` | `{ turnId, delta }` |
| `turn.completed` | `{ turnId, kind, content, format, seq }` (full text, so the client can reconcile) |
| `state.changed` | `{ status, stage, currentIndex, currentDifficulty }` |
| `question.changed` | `{ sessionQuestionId, position, title, difficulty, view: QuestionViewDto }` |
| `assessment` | `{ sessionQuestionId, turnScore, nextDifficulty, reason }` (shown after each question) |
| `code.result` | `CodeRunResultDto` (sent for submit; mirrors the HTTP response) |
| `evaluation.progress` | `{ status: 'PENDING'\|'RUNNING'\|'SUCCEEDED'\|'FAILED', step? }` |
| `error` | `{ code: 'AI_UNAVAILABLE'\|'AI_INVALID_OUTPUT'\|'TOKEN_BUDGET_EXCEEDED', retryable: boolean, turnId? }` |
| `resync` | `{}` |

## 11. Rate-limit classes

| Class | Limit | Key | Routes |
|---|---|---|---|
| `auth` | 10 / min | IP | login, register |
| login lockout | 5 failures / 15 min | email + IP | login (separate counter; locks even the correct password until it expires) |
| `refresh` | 30 / min | IP | refresh, Google start/callback |
| `ai` | 12 / min, burst 4 | user | answers, hints, start, retry-turn |
| `code` | 20 / min | user | code/run, code/submit, admin validate-tests |
| `upload` | 5 / hour | user | resumes POST, voice transcribe |
| `session-create` | 10 / hour | user | sessions POST |
| `api` (default) | 120 / min | user, or IP when anonymous | everything else under `/api/` except `/api/v1/health` |
| `webhook` | none (signature-verified) | — | webhooks |
